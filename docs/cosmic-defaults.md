# COSMIC defaults

COSMIC reads each setting from `~/.config/cosmic/<component>/v<N>/<key>` and
falls back to `/usr/share/cosmic/<component>/v<N>/<key>`. cosmic-blue ships its
defaults in `system_files/usr/share/cosmic/` (copied over the Fedora ones by
`build_files/20-cosmic.sh`). The theme is the exception: it is generated by
`build_files/theme` so that every derived color matches the accent.

A default only reaches accounts that never changed that setting.

## Proposing settings from a running system

1. Set COSMIC up as wanted, then run `ujust export-cosmic-config`.
2. It writes `~/cosmic-config-<date>.txt`: every changed setting as plain
   text, with a list of what was left out.
3. Read the file, then share it (issue, pull request or chat).

The export leaves out the computed themes (rebuilt from the `.Builder`
settings), the keyboard layout (set from the installer), and any file that
names the home folder or the user name, is binary or is bigger than 64 KB.

## Review rules

Each exported setting is reviewed, never copied as is:

- **Theme** (`CosmicTheme.*.Builder`): changes go into `build_files/theme`,
  not into static files. The accent stays `#4f8dff` (dark) / `#1d47c4`
  (light), dark mode and frosted glass stay on unless decided otherwise.
- **Icons, cursor, wallpaper**: stay the cosmic-blue ones (`CosmicTk`,
  `CosmicBackground*`).
- **Hardware-specific**: displays, scaling, touchpad, power and anything that
  depends on one machine is dropped.
- **Per-user**: keyboard layout, clock format, language and anything personal
  stays with the installer and `cosmic-initial-setup`.
- **Panel, dock, applets, shortcuts, window management, app settings**: taken
  when they suit most users, and checked against the image (applets and apps
  must be installed, shortcuts must not clash).
- Only keys that differ from the COSMIC default are added, with the same
  `v<N>` folder as the installed COSMIC version. When COSMIC moves a component
  to a new version folder, the default has to move too.
